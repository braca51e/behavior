# Validation harness (local, CPU-only)

A self-contained harness that verifies the b1k solution is **functional and
submission-ready without relying on external challenge testing** — no simulator,
no GPU, no 3.27 TB demo set. It is the local stand-in for the organizers'
`omnigibson.eval` driver + `raw/score_utils.compute_final_q_score` scoring.

## Run it

```bash
# full harness (unit tests + live-server + edge cases + scoring + report)
scripts/validate_submission.sh                 # ~20 s on CPU
python3 validation/run_validation.py           # same thing
python3 validation/run_validation.py --quick   # skip the live-server gate

# score an existing sample or real submission folder (format + exact official Q)
scripts/validate_submission.sh validation/sample_data/standard.public.b1k.nous.20260910
scripts/validate_submission.sh /path/to/standard.public.b1k.nous.20260912

# regenerate the sample datasets + frozen expected outputs (deterministic, seeded)
python3 validation/make_sample_data.py

# pytest gate (runs in CI)
python3 -m pytest tests/test_validation.py -q
```

The harness writes `validation/validation_report.md` + `validation_report.json`
and exits 0 only when every gate passes.

## Gates

| # | gate | what it verifies |
|---|---|---|
| 1 | unit-tests | `pytest tests/` (115 tests): protocol msgpack round-trip on the 15 MB recorded obs fixture, 31-skill taxonomy, skill-plan miner, progress watchdog state machine, odometry, controller clamps/deadband/receding-horizon/park, Q/time_score aggregation, no-privileged-import boundary, and this harness's own validator tests |
| 2 | fixtures | the recorded fixtures exist (`obs_payload.bin`, `action_23d.bin`, 5 metrics JSONs, `annotations.jsonl`); regenerates deterministically if missing |
| 3 | live-server | drives the real `B1KServer` per fixture task (0/1/3) on the recorded obs: 30 steps each, every action a **finite 23-dim** vector with base velocity within the `r1pro.yaml` output limits |
| 4 | edge-cases | malformed / unusual inputs are handled safely: empty obs, proprio-only obs (no cameras), non-dict binary rejected, wrong-dim action rejected, base-velocity clamp exact, out-of-bounds instance rejected, unknown-task filename rejected, single legal rollout passes, malformed folder name rejected (no crash) |
| 5 | sample-data | the generated sample submissions exist and re-score to their **frozen** `expected_*.json` aggregate scores within 1e-12 (round-trip) |
| 6 | scoring | the local `validator` reproduces the *exact* official `score_utils` math: hand-computed aggregation case, the official `time_score` formula across 6 values, and (when the simulator env is importable) live parity against `raw/score_utils.compute_final_q_score` |
| 7 | report | writes the report + verdict |

## Sample datasets & expected outputs (`sample_data/`)

Generated by `make_sample_data.py` (seeded, deterministic, CPU-only):

* `standard.public.b1k.nous.20260912/` — a **complete** public-testset
  submission: 100 tasks × 20 public instances (301–320) × 1 rollout = **2,000
  metrics JSONs**, each named `<task_name>_<instance_id>_<rollout_id>.json` and
  following the exact spec §7.1 schema.
* `standard.public.b1k.nous.20260910/` — a small **sample** submission (tasks
  0–2, instances 301–305 = 15 JSONs) drawn from the same seeded values, for a
  cheap thing to score in a fresh checkout.
* `expected_standard.public.b1k.nous.<date>.json` — the **frozen expected
  aggregate scores** for each sample (`overall_q`, `overall_task_sr`,
  `overall_time_score`, per-task Q). These are the reference outputs: if a
  future change alters the scoring or validator, the gate-5/6 round-trip
  against these files fails and tells you exactly which value drifted.

Per-rollout values: `q_score.final` ∈ {0, .25, .5, .75, 1.0} (partial credit),
`time.normalized_time` ~ U(0.6, 1.9) (time_score spans negative..positive),
normalized distances ~ U(0.2, 1.4). Frozen full-sample result: **Q=0.4575,
task_sr=0.14, time_score=1.199** (2000 rollouts).

## The scoring contract (why the harness reproduces it exactly)

The harness' `validator.get_scores` mirrors `raw/score_utils.py` (v3.9.2), the
authoritative code:

* **Per-rollout** `time_score = 1.5/(1.5−1) − 1/((1.5−1)·normalized_time)`
  (= `3 − 2/normalized_time`).
* **Per-task**: every average (Q, task_sr, time_score, base/left/right
  distance) divides by the **full** instance count (20 for public, 20 for
  hidden), so *missing instances and missing tasks count as 0*. `task_sr`
  counts rollouts with `q == 1.0`.
* **Overall**: each metric is the mean of the per-task values across **all 100
  tasks** — the single number that ranks the leaderboard.

Note the distinction this harness preserves end-to-end: **fixture / sample
verification is not a leaderboard Q**. The sample scores above come from
*synthetic* seeded metrics, exactly like the recorded-obs serving check; a real
`Q` requires `--mode sim` on an OmniGibson v3.9.2 + GPU box
(`scripts/self_eval.sh`, `MODE=sim`). The harness proves the *pipeline and the
math* are correct and submission-ready; the simulator proves the *policy*.

## Files

validation/

├── validator.py          # exact official score_utils math + submission validators
